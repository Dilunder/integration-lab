# Integration Lab

Локальный стенд для повторяемых тестов входящих вебхуков.

## Запуск
Требуется Docker Desktop с Linux-контейнерами.
В PowerShell 7 из корня проекта:
```powershell
./scripts/init-env.ps1
docker compose up -d --build
```
Откройте http://localhost:8088 и введите LAB_API_KEY из локального .env.
Секреты генерируются случайно и не попадают в Git.
Для остановки: docker compose down. Данные PostgreSQL сохраняются в Docker volume.

## Первый тест
Выберите Try fixed handler, затем Save & run.
Пять одновременных событий создают одну запись: PASSED.
Try broken handler демонстрирует FAILED при пяти успешных HTTP-ответах:
ошибочный обработчик создаёт пять записей.
Demo хранит данные в памяти; его перезапуск очищает только демонстрационные заказы.

## Сценарии
Шаги исполняются по порядку; переставляйте их стрелками.
copies задаёт число одинаковых доставок, parallel включает параллельную отправку.
delayMs — пауза перед шагом, а не таймаут ответа.
pointer — JSON Pointer (/count), expected — JSON-значение (1, true, "paid").
Пустое expected отключает проверку JSON; ожидание JSON null пока не поддерживается.
{{runId}} заменяется UUID запуска в теле и путях.
Probe опрашивает GET API до совпадения значения или истечения срока.
Если API не раскрывает бизнес-результат, его проверяет внешний тест команды.

## Подключение приложения
Добавьте точный origin в LAB_ALLOWED_ORIGINS в .env через запятую и пересоздайте backend.
Внутри Docker localhost относится к самому контейнеру. Для приложения на Windows
используйте http://host.docker.internal:ПОРТ и разрешите ровно этот origin.
Redirects не выполняются. Это инструмент для доверенной локальной команды,
а не безопасный публичный SSRF-прокси. Разрешайте только контролируемые адреса.

## События
Вставьте тело события или загрузите JSON в Event library.
Внешний тестовый отправитель может сделать POST на
http://localhost:8088/api/inbox/ЗНАЧЕНИЕ_LAB_INBOX_TOKEN.
Endpoint сохраняет только тело, не заголовки авторизации. Не используйте реальные секреты.
Подписи провайдеров пока не реализованы. Для авторизации задайте LAB_TARGET_HEADERS в .env: JSON-объект, где ключ — точный origin, значение — объект HTTP-заголовков. Заголовки применяются к доставкам и probes только этого origin и не экспортируются со сценарием.

## CI
Передайте LAB_API_KEY через окружение, затем:
```text
node scripts/run-scenario.mjs examples/duplicate-fixed.json
```
Код 0 — PASSED, 1 — отрицательный результат, 2 — ошибка инфраструктуры/клиента.
Артефакты JSON и JUnit XML сохраняются в artifacts.
LAB_URL и LAB_REPORT_DIR задают адрес стенда и каталог отчётов.
Запускайте тесты только на изолированных данных.

## Проверки и ограничения
mvn -f backend/pom.xml test требует Java 21, Maven и работающий Docker (Testcontainers).
В frontend: npm ci; npm run build. Браузерные тесты требуют запущенный Compose,
LAB_API_KEY и npx playwright install chromium.
Нет публичного SaaS, RBAC, отмены запусков, произвольных скриптов и симуляции внешних API.
Только POST доставки и GET probes, максимум 30 доставок, 20 шагов, 2 активных запуска.
Response body ограничен 64 KiB; request body — 32 000 символов на шаг.
История отображает последние 100 запусков/событий; автоматической очистки пока нет.
Один backend-процесс: кластерный запуск не поддерживается.
При перезапуске незавершённые тесты становятся INTERRUPTED, а не автоматически повторяются.
